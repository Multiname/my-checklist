# My checklist — документация

Точка входа. Приложение — один экран со списком категорий и пунктов-чекбоксов,
только Android, данные — в SQLite на устройстве. Зачем и по каким критериям —
[ProjectIntent.md](ProjectIntent.md).

## С чего начать
- **Новая задача по поведению:** [features/](features/README.md) → [Project.md](Project.md)
  (раздел функции) → [Design.md](Design.md) (если меняется вид) → [Verification.md](Verification.md)
  (что уже подтверждено).
- **Правка кода:** [Project.md](Project.md), таблица «Как читать этот документ» —
  функция, спека, раздел и код в одном месте.
- **Запуск и сборка:** [Environment.md](Environment.md), запуск на телефоне —
  [скилл run-on-device](../.agents/skills/run-on-device/SKILL.md).
- **Что осталось:** [KnownIssues.md](KnownIssues.md).

## Статус
Этапы 1–3 пройдены: каркас и запуск на телефоне, категории (создание, выделение,
переименование, перемещение, удаление), пункты (добавление, выделение,
переименование, перемещение внутри и между категориями, удаление, отметка),
хранение в SQLite. Сейчас идёт полишинг — открытые пункты собраны в
[KnownIssues.md](KnownIssues.md).

## Правила ведения документации
- **Один факт — в одном документе.** Требование к поведению живёт в
  `features/`, число или цвет — в `Design.md`, «как сделано и почему» — в
  `Project.md`, «как проверено» — в `Verification.md`. В остальных местах —
  ссылка, а не копия: копии расходятся.
- **Спека не описывает реализацию.** Формулировки вида «поле ввода», «`Stack`»,
  «прокси» — только в `Project.md` и `Design.md`.
- **Историю не пишем.** В документах — текущее состояние; порядок появления
  функций и хронология проверок живут в git (см. таблицу задач и
  `git log`). Это относится и к обоснованиям: остаётся причина («почему так»),
  а не пересказ «раньше было иначе».
- **После правки кода** обновляются затронутые разделы `Project.md` (и `Design.md`,
  если изменились параметры); `Verification.md` — только когда поведение реально
  проверено на устройстве.
- **Формат:** UTF-8 без BOM, заголовки `#` → `##` → `###` (один `#` на
  документ), ссылки относительные и с прямыми слэшами. Переводы строк git
  нормализует сам (`core.autocrlf=true`), выравнивать их не нужно — главное не
  смешивать LF и CRLF в одном файле.
